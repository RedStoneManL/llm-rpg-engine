# 物品归还约定：当前支持边界

CLI 从玩家当前原话识别物品归还承诺，不从模型正文创建义务。入口分类为
`none`、`clarify`、`ready`；对象或日期不清楚时提问，保留实际回复，世界、时间、
存档和叙事缓存均不推进。意图调用失败也保留本次实际回复，可继续补充。
每个合法玩家行动需要一次独立意图分类，结构错误最多修复一次。

例如：先说“我答应归还蓝伞”，再回答“还给阿林，第2天中午”。宿主核对真实物品、
归还对象、玩家身份和现有世界时钟，原话及逐字证据随不可变创建事件一起保存。
支持明确的今天、明天、后天或第 N 天及明确时段（早晨/中午/下午/夜晚等解析器
支持的同义表达）。日期与时段可来自不同实际回复；不会替“明天某个时候”猜中午。
逐字引用只能证明原话来源，不能证明语义蕴含；否定、条件句、转述和假设由分类模型
判断，仍有误判风险。模型不得自行提供绝对日期替代可验证的日期原话。

## 账本与履约

- 新事件为 `item_return_promised` 和 `item_return_fulfilled`；旧的自由事实和旧事件
  不迁移、不改写，不把原有承诺文本自动变成新账本。
- 记录物品、债务人、归还对象和绝对 day/band。创建后不能改写或取消；本增量不含
  金钱、协商、债务或泛用 PromiseSystem。
- 截止按离散 day/band 表示，可选 boundary：inclusive（含旧记录缺省）在超过该时段后逾期；exclusive（“之前”）在进入该时段时即逾期，不假定分钟精度。
- 中文绝对日期支持规范序数第一天至第九十九天；原有正整数阿拉伯日及相对日期继续支持。见 [截止边界说明](RETURN_DEADLINE_BOUNDARIES.md)。
- 履约由本次原子行动结束时 canonical `held_by` 的真实归还决定，不靠正文声称。
  必须存在创建之后的新交接证据；同持有人 B→B 不能冒充归还。暂时交到 B 又拿走
  不算行动结束时完成。显式请求履约但后续钩子移走物品或改变履约时间会拒绝整个行动；自动履约使用
  最终行动时钟，不重写已暂存的显式履约时间。
- 新转移同持有人操作拒绝；历史事件仍可回放。来源和履约只验证物理持有，不能
  证明法律所有权、授权、同意或对承诺的社会接受。
- 创建、叙事、交接和履约一起原子提交，写入失败不推进；重开恢复记录，撤销恢复
  之前的 open/fulfilled 状态。

## 可见性与运行限制

仅约定双方读取记录，并按 POV 过滤引用。债务人可记住订立时实际可见的物品和
归还对象身份，即使之后离场；这不泄漏现在的位置、持有人或秘密。归还对象不接收
玩家的完整原话证据，避免旁带其他私密行动。提示、查询工具和摘要锚点都读取同一
受过滤的账本，摘要不是权威事实来源。

尚未登记的澄清上下文仅在当前 CLI 运行期保存，不跨进程重开保存；世界版本、主角
或时钟改变会要求重新完整陈述。比较模式收到新约定会明确暂停，保留原话并要求
`/compare off` 后继续，不展示在未暂存约定的世界上生成的候选。

## 验证

离线测试覆盖否定/条件/转述、歧义、跨回复日期、隐藏对象、方位隔离、存档/撤销、
摘要、写入故障、后台绕过和事件篡改。默认测试不会调用付费模型。

```bash
python -m pytest tests/loop/test_return_intent.py tests/systems/test_return_commitments.py tests/test_return_commitment_integration.py tests/test_deepseek_returns_harness.py
python scripts/verify_deepseek_returns.py --live --output-dir ./campaigns/return-check
```

真实脚本要求预先安全配置 `DEEPSEEK_API_KEY`，锁定官方 `deepseek-flash` 并先检查
模型列表，最多 16 次 POST、单次 4096 输出 tokens、不自动重试或替换模型。
五条真实输入覆盖含糊承诺、补充详情、查询、无交接假履约、实际归还；分别检查
重开、最终归还撤销，另有明确标注的确定性逾期投影。原始正文需人工审阅，不能把
有限账本测试等同于通用语义保证或长局验证。

### 会话费用护栏

有会话总预算时，可给 `BoundedDeepSeekProvider` 传入持久化 `BudgetLedger`。
发送前持久化最坏费用预留，接收有效 usage 后才按实际 tokens 收回差额；失败或缺失
usage 保留全额预留。按序列化请求 UTF-8 字节数加保守开销估计输入上界，并同时
限制输入大小与 4096 输出 tokens；不把 token 数估计称为精确分词。
金额是按价目表的保守估算，不是账户实际扣款；缓存折扣和谷时优惠不用于扩充预算。
