## A. 先完成两个可验证的机制设计

### 导演去重

现有草稿加入 `DirectorNoveltyPolicy(twist_window=3, event_type_window=1)`，从活动的 `director_fired`
事件读取近期主题；中性“无反转”保持可选，表太小时回退到最久未用项，并记录选择依据。
零窗口设计用于消融。草稿**没有测试，也未接入本分支**，是否正确需先审阅，不能靠 `git apply --check` 认定有效。

至少检查：撤销/冷重开后选择一致性；活动事件顺序；随机流不污染其他裁决；所有主题都被冷却/单项表；
隐线触发是否受影响；不为了新鲜而每回合强制反转。先确定不变量，再测普通入口，而非只测 helper。
真实模型对照评估重复是否下降、故事是否更自然，不能把换了标签当作玩法改善。

### 已有暗线的接受与降级

已知旧测试保护 `quest_opened` 创建的新任务被显式接受。当前源码中 `accepted_by_player=True`
由 `quest_opened` 设置，已有暗线的 `quest_surfaced/quest_advanced` 不必经过同一路径。
先构造“已存在的暗线 → 玩家明确接取 → 离场/等待 → 回访”的普通入口红例。
必须区分“线索被发现”“承诺接取”“只是询问”“任务已经完成/放弃”；禁止所有 surfaced 任务都自动永久活跃。
若反例不成立，记录未复现原因，不把假设当作已确认 bug。

## B. 新长局 runner 的必要能力

- 固定合成世界、玩家目标与证据点，同时保留自然行动空间。不能每轮都在输入里复述答案以制造记忆成功。
- 稳定 action_id、连续 turn/day、模型路由标识、请求哈希、原始 messages/tools/response、每回合事件差异与状态快照。
- 任一请求/后台钩子失败保留现场；从已提交边界续跑，不能手工改历史让失败消失。
- 保存会话冷启动、摘要/压缩、撤销、重开和受众传播的检查点；保持正式默认后台钩子。
- 保存模型调用数与种类；只有提供商返回的 usage 才能记录 token。mailbox 等待时间不得冒充 API 延迟。
- 对每个 actor 记录允许观察的来源/检索集合；审查与生成的可见输入相隔离。
- 分开计数：尝试行动、成功提交、撤销、当前活动回合、模型请求、重放请求。不能把多个独立短局的数字相加称为连续100回合。
- 显式停止条件与恢复元数据；新轮次结果写新目录，不覆盖已提交的 2026-11-11 证据。

## C. 20 → 30 → 100 的验收

| 阶段 | 场景重点 | 通过条件 |
| --- | --- | --- |
| 首20回合 | 私聊、异地人物、同场新NPC、两地往返、接取已有暗线、承诺与时间变化 | 没有未解释的拒绝/双提交/事实与正文冲突；主线可继续；私人信息不串 |
| 扩至30回合 | 摘要后原话检索、撤销后重开、NPC离场追赶、同类导演桥段重复率 | 原话有来源；撤销内容不复活；暗线不过度冻结/降级；无意义重复得到改善 |
| 同一连续场景扩至100 | 多日、多暗线、交错承诺与调查、跨线后果、信息传播与长距离回访 | 全程事务/恢复不变量成立，关键语义场景无未解决缺陷，逐段体验审查无持续漂移 |

如果中途修改代码，记录版本分界和原失败；修复后对失败做精确回归，并在最终冻结版本完成一轮可归因的100回合验收。
不能把修前/修后的若干成功片段拼成“一个版本连续100回合无问题”。未达到目标就明确记录进度和阻碍。

## D. 每段审查表

1. **世界状态**：位置、时间、物品、资源、任务与约定是否与已裁决后果一致？玩家没看着的线是否合理推进？
2. **角色认知**：说出秘密的人在哪获得信息？回忆是自己的经历、他人说法还是世界真相？错误信念是否有依据？
3. **因果与体验**：选择是否改变下一步？角色是否延续关系/目标？重复桥段是否合理？剧情是否只剩询问与等待？
4. **历史**：按日期/受众可查原话；摘要遗漏仍可定位；没有把猜测/未说出口心念变成发言。
5. **恢复**：重复 action_id 不重做；取消/失败不半发布；撤销后原文、索引、摘要、派生记忆与回执一致；冷重开一致。
6. **成本**：前台/后台调用分别计数，复杂度是否随历史无界增长；没有为每个无关 NPC 每回合调用模型。

代码检查与实际正文都要看；同一 DM 的自评不是独立盲评。有限验证只能支持覆盖范围内的结论。
