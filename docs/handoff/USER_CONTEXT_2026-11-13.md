# 用户上下文与决策 · 2026-11-13

这是当前可见会话、已提交资料和源代码的交接摘要；不假装是完整历史逐字记录。只保留与项目有关的内容。

## 产品目标与偏好

用户要一个能长期游玩的单人 LLM RPG 世界，人物、暗线、承诺和事实在长期执行中持续存在。
特别在意“引擎是否真的按设计运转”，不接受只有提示词宣称或账本正确而正文体验错误。
中文沟通，持续执行；自主发散检查相关问题，按共性根因聚合修复，而非用户每提一个才补一处。
游戏体验优先，但不放松原话、因果、权限和恢复边界。模块重构、Prompt、流程和数据结构都可以调整。

## 最近请求的顺序与关键原话

1. 询问能否迁移到 DeepSeek Harness、是否能作为 DSH 插件发布，担心现有实现太重。
   初步方案：保留 Python 世界内核，通过 DSH 插件接工具、UI、配置和模型；全面重写运行时不是当前首选。
2. 要求查同类插件，发现 Agentic Roleplay、Agent RP、LikeTavern、RP Tools、Portable Tavern。
3. 用户：“综合一下取长补短，我们应该也有自己的东西……综合出来一整套解决方案”。
   已形成自有内核 + 角色认知/自主行为 + 世界进程调度 + DSH 适配的候选架构，保留直接采用第三方的对照选项。
4. 用户：“他们这些你也得验证以后再接入……做一些简单的消融测试，我们再一点点合入”。
   因此不能因上游 README、功能表或测试数多就采用；已做第一轮真实组件实验并发现阻止准入的反例。
5. 用户：“你用6.1 terra作为 dm进行真run测试效果，我们实际看看怎么进去”。
   实际是原生 `gpt-6.1-terra` 按正式请求生成，正式引擎提交，非 DSH 宿主运行；11 行动/35 响应。
6. 用户：“你先设计并且调整我们的这些能力，至少在一个100回合的游玩中不能出问题，你可以20、30”。
   当时采用的执行解释：20 → 30 → 连续 100 回合渐进，每段审查并修复；不是分别跑20和30凑成100。
7. 最新用户：“你先别在这里实现了……我要迁移到codex里面工作……把当前的work整个上下文，你的研究等等……放到我们的这个harness分支里面……agent拉取这个分支就能继续work”。
   这条暂停当前 Work 功能实现，转为交接打包与推送；并不取消长期目标。

## 已接受的工程方向与尚待选择项

- **角色决定意图，世界内核裁决结果，叙述表达可见后果。** NPC 可拒绝、误解、隐瞒；不能全知或自行改写权威事实。
- 玩家和 NPC 的意图/宣称不等于已发生的效果；承诺送信不代表信已送达，无法支付不能叙述交易成功。
- 原话检索与拟人回忆分开。玩家查历史要可定位原文、日期和受众；摘要只是导航，不能伪造精确记忆。
- 其他地区的故事应推进并影响世界，如封桥影响信使、延误影响阵营；不只在玩家眼前才存在。
- DSH 优先作为交互与能力接入层；宿主不能再次续写/改变已经裁定的剧情，不能把 GM 全量资料放进共享聊天。
- 概念借鉴不等于抄入第三方源码。尤其 Agentic Roleplay 的 GPL-3.0-only 与本项目许可证需在源码复用前明确处理。
- 若同场景对照证明第三方引擎加少量扩展更好维护，应重新评估整体采用，不能被现有代码量绑住。

## 必须继承的约束

- 6.1 Terra 是最新 DM 指定，早期 5.6 Terra / Luna / Astra 的记录不覆盖它；不能静默替换。
- 历史要求“不使用用户 Codex 额度”用于 RPG 模型测试。用户转到 Codex 编程不是自动授权把其 Codex 配额用作100回合DM调用；新环境需核实实际路由/计费，不能猜。
- 当前仅交接，不启动新模型运行、不继续导演或暗线修复。
- 不重复询问此次已明确要求的提交/推送；不强推、不覆盖 main、不随意外传存档/密钥或部署。
- 不因历史 B1 HOLD 停工；该暂停已解除。具体可用能力仍须验证。
- 测试必须体现真实公共入口、正式工具与持久化；不删合理失败测试、不换假输入来掩盖问题、不把失败样本覆盖掉。
- 100回合零已知关键问题是本次验收目标，不能由有限样本推断“所有未来游玩绝不会出错”。

## 不应被误认为用户要求

用户没有要求此时发布 DSH 插件、重写成 TypeScript、全盘采用 Agentic Roleplay、启用所有 NPC 多 Agent、部署公网服务或开放多人。
先做候选机制对照和可玩的长局闭环；没有实测的设计要写“计划/候选”，不能写“已完成”。
