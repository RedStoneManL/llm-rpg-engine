# Narration after repaired physical outcomes

The recorded DeepSeek stress turn14 proposed a bell transfer keeper → player,
although the canonical holder was already player. Validation rejected it;
modular repair returned items:[], but the published prose still said the keeper
put the bell into the player's hand. This was a demonstrated repair/prose
mismatch, not merely a hypothetical invalid response.

A host-only marker now compares final physical/time declarations with the
usable whole proposal behind their narration. The signature covers items,
moves, absolute clock outcome, reserved physical relations, and object
creations. Clock reasons, cast goals, and equivalent time representations do
not trigger a rewrite. New complete narration resets its baseline; frozen
prose retains responsibility. Dropped invalid sections still reject the action.

Before primary events are applied or narration recorded, a flagged action makes
one fresh narration-only call. Its allowlisted packet contains actual player
intent and POV-filtered before/after physical state plus approved transitions.
It excludes old prose, repair diagnostics, raw event summaries, clock reasons,
free-form ownership facts, private system slices, and arbitrary entity attrs.
The model can return only a narration string, with no authority to change effects.
Invalid/empty output rejects the staged action instead of falling back to stale
prose. Stored, displayed, and conversation-cache narration use the same result.

Initially valid turns with unchanged effects add no call. Prepared candidates
retain the host marker through the normal gateway; direct apply rejects a
still-flagged candidate. Valid comparison candidates reconcile before display,
then clear the flag so selection does not repeat the call. These prepared and
comparison routing safeguards were independently code-inspected after the
ordinary-path native samples; comparison generation itself was not sampled.

## Ordering and limits

The outcome preview copies world state, uses the existing creation ordering,
normalizes clock, and reproduces kernel day/scene projection before each owner
applies an event. It describes the primary foreground action only. Background
hooks run afterward and may produce subsequent offscreen events; they are not
included in the rewritten foreground narrative.

The view is deliberately local and bounded. NPCs lacking canonical location
records and transfers leaving visible local scope may be under-described;
missing/redacted ownership is unknown, not proof of emptiness. This is not a
general solution for missing effects, arbitrary factual contradictions, or
narration-only success claims that never trigger a physical repair. A language
model may still write an unsupported claim despite the outcome instruction.

## Actual model evidence

The [compact evidence](reports/2026-10-07/native-repaired-outcome-after.json)
separates two cases:

1. Historical replay used the exact recorded DS original and actual items:[]
   repair. Those two inputs are historical, not newly generated model outputs.
   One fresh Astra rewrite said “铜铃就在自己身上…无须再接回”. Approved sections
   remained unchanged, no item transfer was emitted, and the bell stayed with
   player. While rewriting was pending, the durable store still held only its
   81 seed/history events. Displayed, recorded, and cached text matched.
2. A separate fresh normal play_loop generated both intent and narration. It
   recognized the existing possession and explicitly said “这回并没有发生交接”.
   It committed with no repair and no rewrite call. This used two fresh native
   completions and left possession unchanged.

There were three fresh native completions total. No new DS call, offline unit
campaign, or fabricated failure response was used. Atomic failure handling was
reviewed in code; the successful observations do not prove universal prose
fidelity. Native response files used atomic delivery for these cases.

The historical replay also preserved an existing residual: approved clock.reason
still said “交接”, and a later backstop hook reused that string as a hidden quest
summary. The foreground rewrite did not change those effects or fix background
metadata. That evidence is retained rather than claiming the entire world state
or all future recaps are semantically repaired.
