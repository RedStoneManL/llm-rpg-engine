# Opening publication contract

Generated production openings and rerolled openings use the same semantic finalizer and host approval as foreground candidates. The staged genesis world is authoritative: opening prose cannot relocate an existing NPC, transfer an item, introduce a new entity, or advance time. This slice permits no opening effects. A failed audit/correction aborts the atomic genesis batch; it does not publish a fallback opening.

The generator sees the actor's canonical local physical state and bounded, POV-authorized descriptions of co-present people. The old all-NPC/all-thread world-building summary is not sent to this production opening call. World-generation seed selection and its priority relative to a player's pitch are unchanged.

An opening returns narration and explicit `introductions` linking existing local IDs to display labels. Host validation checks source containment, current unique co-location, visibility, label collisions, and literal publication spans. A label found inside a sketch is not deterministic identity proof: the same semantic extraction call receives the already-authorized description and independently classifies the proposed binding as introduced here, merely mentioned, or uncertain. Ambiguity cannot silently grant identity. Extraction and referent interpretation remain probabilistic.

The host-only opening context is included in the candidate seal. Correction preserves that context and all empty effects, edits only supported issue spans, and re-audits once. The host rechecks the staged source immediately before appending narration. Supplied opening prose keeps the previous stripping of leading/trailing whitespace, is audited without semantic rewriting, and fails if unsupported. The legacy low-level prose generator remains available; explicit offline/fake genesis retains its existing unaudited compatibility path. Neither is a production-model audit guarantee.

A separate private `opening_observed` event links approved final text, actor, source time/location, and bounded introduction spans. It is not a player action or a knowledge grant. Normal introduction and opening sources share readers; an off-scene remembered NPC exposes only existence and the original introduction, not current location, goals, or private attributes. Old logs without the new event remain unknown. New source events replay only against their preceding narration and canonical context; reroll retracts both with the opening boundary.

The source span retains at most the first 2,048 characters. Proposed introductions must occur within that bound, and publication fails if an audited introduction cannot retain its source. Names beyond the bound are not silently promoted to remembered identities.

## Calls and limitations

Normal new opening: one structured generation call and one semantic audit. A supported correction costs one patch call and one re-audit. Binding review is part of that same audit. Full world generation before the opening is unchanged. Ordinary turn audits use the same v5 extraction schema; their physical claim categories are unchanged.

This does not solve world-building tone selection, arbitrary narrative facts, NPC truthfulness, or the existing distinction between initial item placement and a completed handoff. A passing model extraction does not prove all prose claims were found. Body locations, visible custody, and direct passages are checked only within the established semantic scope. Background events and clock reasons are not newly made narrative authority.

## Shared source consumers

The published-introduction reader is shared by context recall and character queries. Physical outcome packets now include the same actor-owned display binding as a separate `published_display` field on already-visible Person entries; canonical `name` is retained. An introduced label does not establish current presence, a true name, or private knowledge. Colliding canonical, historical-display, and candidate labels must not be treated as a unique match merely because one source is canonical.

Semantic approval binds the actor's validated introduction source records. Prepared comparison preparation/restoration and write-edge checks use that same actor-specific digest. Changing the underlying source invalidates an old approval.

Summary identity and narrative provenance dispatch through the same opening/player-source validator. Turn zero is bound only when a valid, uniquely linked opening observation exists and replays against the original narration/context. Supplemental display labels must literally occur in the corresponding historical text and retain their published-display category. Historical custody still comes from the projection at `narration_recorded`, not later source-record or present-day state. Missing legacy sources stay unknown; this does not retrospectively repair old prose.
