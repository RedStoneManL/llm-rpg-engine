# 有来源的玩家原文记忆

本增量解决一个明确的读取缺口：当较早对话退出最近8次交换，且剧情摘要省略细节时，
模型还应能看到相关的真实玩家原句，而不是把摘要补写成精确回忆。

## 三种信息不能混为一谈

- 玩家原始输入：证明玩家给引擎输入了这些文字，可能是意图、问题、假设或台词。
- 已发布叙事：证明游戏展示过这段正文，不自动证明其中每个动作已进入事实账本。
- Canonical效果：位置、持有关系、资源、承诺等各自系统记录的状态变化。

找到“我把伞交给B”这条旧输入，不意味着交接成功；找到“难道是从何桥守借的吗？”
也不能把何桥守变成出借人。原文引用不能授予NPC知情或证明他听见/说过某句话。

## 记录与读取边界

正常玩家回合由宿主记录原样传入run_turn的输入，连同角色、源事件/回合、行动开始及
提交时的时间和地点。只随已提交的回应进入现有事件批次；没有新队列或另一套存档。
回合拒绝不留下已提交来源。事件摘要为通用文字，不把私人输入复制到全局时间线。
旧存档不会回填或推测缺失原文。

读取必须绑定实际Person角色，在匹配、计数或截断前先隔离该角色的记录。普通POV
投影不暴露原始日志；上下文只加入经过专用读取器选择的少量证据。后台效果引用
不直接呈现给叙述者，不用在场名单推断别人肯定听见。

匹配优先使用可见实体ID/名称与记录关联的实体，再参考文本重合；为相关实体保留
较早和较新的证据，避免后来的反复提及挤掉起名等首次信息。短输入尽量完整保留；
长输入使用原文位置明确的片段，并标出截断和覆盖不足。没有找到匹配不代表从未发生。
这不是通用语义检索，也不保证任意换一种问法都能找到正确记录。

## 验证目标和限制

离线验收会让T1的“雨燕，不是归雁”经过多回合、场景切换和故意遗漏细节的摘要，
确认相关问题仍能把完整正反原句送入正确角色的提示；同时检查另一角色、缺失角色、
回滚后以及错误历史前提都不能获得不应有的证据或事实。

这只证明来源记录/检索/提示覆盖，不证明真实模型必然使用证据，也不解决正文凭空
移动、局部修复后正文与效果冲突或NPC独立知识推理。代理403仍阻断真实模型验证时，
不得把离线证据覆盖称为已实测的剧情质量提升。

玩家原文会保存在本地事件存档中，属于角色视角隔离，不是磁盘加密；能读取完整
存档的人也能读取这些记录。这里不记录API凭据，不导入旧的外部聊天或私人文件。


## 已确认的离线示例（2026-10-07）

[端到端回归](../tests/test_player_source_recording.py)通过真实run_turn和事件回放执行：
1. T1输入“我把铜铃叫作雨燕，不是归雁。这只是心里的命名想法，没有说出口。”
2. 再提交13次检查铜铃的动作，切换场景，并写入故意省略命名细节的摘要。
3. 对同一投影移除原始输入记录，旧式上下文不含“雨燕”或“归雁”；保留来源记录后，
   问“我最早给铜铃起的名字是什么，排除了哪个名字？”能取回完整原句及实际源事件ID。
4. B角色仍取不到A的原文；铜铃持有关系不变，没有新增任何knows事实；回滚至T1之前
   后，来源也不再出现。

另有新鲜/继续/强制压缩/Hybrid提示一致性、源日志计数隔离、Unicode原文偏移和私密
名字推断的回归。最终全套2399项通过（1项slow/network排除），独立边界复核通过。
该前后比较是离线证据可用性断言，不是两次真实模型生成质量对照；本轮没有API调用。
