# 外部机制接入准入规则

用户要求（2026-11-11）：第三方声称完成不代表已验证；先测试和做简单消融，再逐步合入。

适用于 DSH 迁移、NPC／记忆／世界调度与分支相关的候选机制。默认先在独立研究分支运行；文档和源码分析仅用于提出假设。

1. 固定第三方提交和依赖版本，保留来源、许可证与源码哈希。测试真实实现；替身只用于外部模型、宿主或明确记录的消融边界。
2. 区分证据层级：作者声明、源码阅读、上游测试重跑、独立场景、消融、真实模型、真实 DSH 安装。任何一层不能代替下一层。
3. 每次只考察一个主要变化。完整实现、关闭该机制、必要的简单基线使用相同场景、预算和输入。包含失败／取消／撤销／重开与一个负对照。
4. 信息隔离要测反事实：角色可见资料不变，只改变幕后真相，角色上下文和检索选择也应不变。检查候选构造、关键词／向量／重排、公共场景文本与工具结果。
5. 引用存在、属于该角色、以及内容支持结论是三个不同要求。角色可以持有错误信念；但不能把无关证据包装成可靠推导，更不能改写世界事实。
6. 消融没有改善也要记录。合法保留“未证明收益”“只改善一个样本”“受另一层保护”的结论。小样本不报普遍成功率；提示词字节数不是 token 或真实调用延迟。
7. 独立场景通过后，才实现最小领域适配，并跑本引擎的共用回归。涉及模型行为时，再比较同模型／同预算的短场景；涉及宿主时，实际安装、切会话、取消和恢复必须验证。
8. 每批合入一个机制，配置可控，具有回退方式。保存问题复现、改动前后结果、未覆盖部分。完整性／认知隔离的已知失败必须先解决。
9. 测试脚本为证明某个反例存在而变绿，不等于候选机制准入。实际准入状态单列在结果报告中。

第一轮结果见 `docs/verification/DSH_VALIDATION_ROUND1.md`。本轮仅纳入研究测试、结果与准入规则；生产运行时接入数量为 0。
