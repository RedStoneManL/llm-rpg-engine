# 游戏体验优先：系统整理与下一阶段

更新：2026-11-04（Asia/Shanghai）。用户已明确要求优先单人游戏体验；本文替代早期“来源底座一律先做”的排序。
工程约束用于维持游戏结果和存档，不另开账户、多人或通用安全工程。已有代码继续复用。

## 当前游戏循环与真实进展

玩家行动 → 当前场景／人物／任务语境 → 提议结果 → 规则校验与修正 → 最终反馈 → 同回合保存 → 后台后果 → 下一次行动。

| 玩家感受 | 已有模块 | 本轮已做 | 仍欠缺 |
| --- | --- | --- | --- |
| 我的行动确实有结果 | `loop.turn`、`strategy`、`resources`、领域 systems | RCV-122：Hybrid 先结构后正文；Author 修正结构后重写正文 | 任意自然语言与效果完全一致仍需实际模型评审；战斗／社交没有通用判定机制 |
| NPC 记得刚发生什么 | `systems.character`、`context.assembler`、知识与 receipt | RCV-123：当前角色卡带已保存 state 与主角对其态度，不增加模型调用 | 还不是 NPC 自主计划；没有凭空补造未记录的承诺、动机或精确原话 |
| 剧情会接着发展 | director、cascade、time、lore、density | 保留现有有界后台、暗线与明账 | 任务阶段和真实行动后果之间的证据／反馈还需系统检查；NPC 离场行动仍依附回合 |
| 我知道现在可以做什么 | GUI／CLI 的人物、任务、地图、出口、物品与近处观察 | 已存在这些读模型，本轮不重复造 UI | 候选行动应从当前局面自然产生，不强制选项或替玩家决定 |

| 我可以核对曾说过的话 | narration 原文、receipt、SQLite/FTS/vector 底座 | 保留现有来源绑定与检索过滤 | 原 input 档案与 locate/open 尚未完整接入；摘要不应冒充逐字记忆 |

## 迭代顺序

### 1. 完成行动反馈与人物连续性首切片（本轮已实现）

先修明显影响沉浸的问题：结果被修改而故事没改；状态存了但下一回合角色卡没读回来。
成果以正常入口收到的 provider 消息、持久化结果和恢复行为验收，不能用假模型输出证明真实文笔。
RCV-122 无修正 Author 一次调用、Hybrid 两次；修正后的 Author 多一次最终写作，正文格式失败最多再试一次。
RCV-123 零额外模型调用、零新事件类型、零存档迁移。

### 2. 任务与承诺产生可感后果（RCV-125 首切片已实现）

单件明确交付已经接通：接取条件 → 实际转移 → 按时／迟交或放弃 → 共享任务账本 → 最近六条公开结局。
逾期仍可继续，旧式自由任务兼容；无奖励自动生成。详见 [RCV-125](../verification/RCV-125-delivery-outcomes.md)。
Terra 5 回合／10 原生响应中，迟交被药师追问，后续未重复交付。反应连贯但平淡；不是长局质量证明。
赴约、护送、数量、NPC 自主计划与长期状态后果仍是后续任务，不因首切片通过而标成完成。

复用 LoreSystem 的明账、阶段、期限和 director 的已有调度，先做一条局部任务的多回合闭环：
接取 → 实际推进 → 到期／履行／失约 → NPC 可观察反应 → 任务账本和下一回合一致。
先审计现有 `loop.lore`、`systems.lore`、`loop.endgame` 和各生命周期测试，避免再造任务引擎。

验收场景：按时赴约、主动拒绝、晚到、带来约定物品、只是口头声称完成、撤回后改选。
“给一个可回应机会”与“替玩家完成任务”必须分开。没有证据时不得仅因气氛合适就自动结算；
此处是后果可信度，不是把游玩流程变成审批表。NPC 反应先复用公开 mood/state，不依赖私有解释系统。

### 3. 节奏与等待时间

按完整回合测量作者、结构修复、最终正文、摘要、cascade／catch-up、投影与发布开销。
优先消除重复工作，再决定哪些维护可以按预算执行；不得在未测量时承诺“更快”。
同场短对话不应每次跳过一个时段；长等待要到达目标时刻，不能总停在准备阶段。
安静回合也可以有意义，不以每轮强行突发事件替代剧情推进。

验收使用同一套 20／100 回合合成场景统计调用次数、修复次数、上下文字符、维护积压与阶段耗时；
再与受控真实模型的响应相关性、冗余程度、可回应性分开报告。不要把 Python 耗时当模型延迟。

### 4. 长程记忆按体验需求接入

当玩家问“那天对谁说过什么”，再提供定位片段 → 打开原文 → 扩展前后文 → 带来源回答。
复用已有 SQLite／FTS 和工具回路；向量可选，不下载权重作为启动条件。
输入档案、来源身份和读取范围是该能力自身的实现条件，不再阻塞无依赖的行动、人物和任务改进。

### 5. 一位 NPC 的自主行动，再扩大世界

先让一个具体角色围绕已有目标提出有限行动，通过现有规则形成可见后果；再考虑多角色和离线推进。
默认关闭的私有解释不作为先决条件，也不改成全角色共享玩家视角。
异步世界、复杂战斗与多人都不是本轮已经实现的能力。

## 评审尺度

每个切片至少回答：玩家能做什么、看见什么改变、下一回合会不会忘记、等待是否增加、失败如何继续。
离线验证负责结构／存档／恢复；真实模型评审负责叙述是否贴合行动、人物是否像同一个人、局面是否值得回应。
