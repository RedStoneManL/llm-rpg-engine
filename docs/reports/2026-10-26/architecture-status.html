01

现状判断与优化方向

这是代码现状报告。实现、离线回归、原生模型样本和未来设计分别标注。

接下来优先优化什么？

先补“原始输入 → 可授权读取的来源 → 逐步查证”这条闭环，并同步推进结果裁定后的最终正文。保留已验证的事务与来源底座；性能优化从减少重复投影和控制上下文增长入手。

底座已经具备

事件溯源、14 个默认系统、严格普通作者边界、同回合原子保存、撤回／冷重开、带来源的分段与递归摘要。

实现 + 回归证据

核心体验仍有断点

普通行动原 input 尚无完整同事务档案；旧原文无法让模型逐步 locate/open；修正结构后正文仍可能保留旧结果。

优先补闭环

长期运行需正视规模

5,000 条未摘要旁白产生约 161 万字符上下文。单回合反复重放和复制历史，背景模拟仍依附前台同步运行。

有测量，未完成治理
问题当前判断应采取的动作
B1 / profiling 是否还暂停？用户已明确解除旧 HOLD。按当前边界继续实现与验证，无需再次申请旧暂停解除。
是否需要重做数据库／上向量服务？目前 SQLite／FTS／NumPy 已可用。先统一来源身份和读取授权；向量只生成候选。
是否应该继续堆摘要？摘要来源链已经补齐，语义仍会失真或遗漏。让摘要提供导航，再读原文；保留“未找到／未核实”状态。
主要验收障碍？本地开发无权限阻塞；远程 API 凭据和 Chromium 缺失。对应验收单独记录；不把环境缺口放大为停止整个项目。

    入口构造

    CLI play_loop 或 GUI PlayerDashboard.action 构造 scene、action_id、expected_revision。明确交流单独产生 host receipt；普通 input 不自动等于 NPC 听到的话。

  2. 02

    恢复检查与快照

    run_turn 先检查已提交 action 和请求指纹；新请求创建 EventBatch，读取同一 snapshot/revision，再注册最终 payload validators。

    loop/turn.py:996
  3. 03

    宿主前置裁定

    登记资源存在时 prepare_resources 解析意图并确定性裁定余额／等待；准备 variation 与已过滤的安全作者交接。

    loop/resources.py:69
  4. 04

    上下文与生成

    produce_turn → strategy.produce；assemble_context 做 POV、系统注入、摘要、事实锚点和能力范围；Author 可调用六个只读工具。

    loop/strategy.py:441
  5. 05

    候选验证与修复

    实体引用补齐 → 系统 validate + narration/resource/authority 检查。局部 repair_sections；有些普通错误耗尽后可丢 section，权限类错误严格拒绝。

    loop/turn.py:342
  6. 06

    暂存前台事件

    apply_turn 依 owner.to_events 转结构为事件；旁白另外记录 narration_recorded，同一 turn。opt-in 私有解释绑定该 narration。此时仍未写入 durable store。

    loop/turn.py:694
  7. 07

    同步后台

    digest → director → cascade → catch-up → lore → 离场 demote → density；各 hook savepoint，追加后按需 project；最后场景推进。

    loop/turn.py:991
  8. 08

    最终事务

    重新核对裁定余额、制作 result sidecar。batch.publish → EventStore.append_many：revision、完整投影 preflight、最终事件权限校验，然后 events/receipt/sidecar 同事务提交。

    engine/store.py:192
  9. 09

    提交后展示

    同步 JSONL 镜像（失败标 mirror_pending）；成功提交后才把 narration 计入策略会话。入口更新 world 并显示已保存正文；可选 transcript 是提交后的另写。

    loop/turn.py:996
  1. 01

    收到相同 action_id

    入口先恢复历史请求上下文，run_turn 从 SQLite 读取已提交 action 与 sidecar。

    loop/turn.py:224
  2. 02

    核对身份

    检查 fingerprint、基础版本、权限模式及是否被撤回。相同 ID 不代表可以重写不同动作；缺少可证信息时保守拒绝／报告未确认。

    loop/turn.py:137
  3. 03

    返回原结果

    合法重试返回原 narration/events/recap_status 与 duplicate receipt；不重新调用作者、不重新扣款、不重复写入。

    app/gui.py:594
  1. 01

    生成或候选失败

    尚在 EventBatch 准备阶段；越权或无法修复的关键旅行失败拒绝，不能将假成功正文当已保存。

    loop/turn.py:342
  2. 02

    普通后台异常

    savepoint 恢复该 hook 的事件、撤回意图与 validators；前台及其他成功 hook 可继续。摘要任务还有 job-local 边界。

    engine/store.py:457
  3. 03

    取消或最终校验失败

    CancelledError 传播，整批不 publish；revision 冲突／最终校验失败在事务中回滚，策略会话恢复旧状态。

    loop/turn.py:996
  4. 04

    已写库但展示／镜像失败

    不能重报“行动未保存”并再跑一次；通过 durable receipt + sidecar 恢复原动作，镜像可补同步。

    engine/store.py:142
  1. 01

    显式撤回

    检查 expected revision 与受保护的创世 turn 0；按完整 turn 标记 retracted，保留历史而非直接删行。

    app/engine.py:272
  2. 02

    重建世界

    project 只应用活动历史；narration、summary、前序 recap 与私有解释随同 turn 撤回；不能复活已撤回来源。

    kernel/projection.py:16
  3. 03

    清理会话与作用域

    CLI／GUI 重置策略缓存，恢复有效 prior scene，避免冷重开或撤回后重复 catch-up。

    app/play.py:271
  4. 04

    重新打开

    build_engine 注册系统，store.snapshot 同时取 history/revision，重新投影；旧 branch 的 action 或未来 source 句柄不能无条件复用。

    app/engine.py:82
“已生成”与“已保存”不是同一阶段

模型输出、修复和所有后台工作都在 durable publish 前完成。SQLite 事务里不进行网络模型调用。返回给玩家的结果必须对应最终成功提交的那一批事件。

后台世界：有哪些钩子，什么时候跑

它们提供世界后果和持续内容，但尚不构成离线常驻的世界模拟服务器。

顺序与入口作用模型／运行方式位置
digest_fleet事件重要性 → 阈值反思；分段摘要与总概要各一次；保守任务兜底可能调用评分／反思／摘要；每项摘要最多一次格式 repairloop/fleet.py:1
run_director按暗骰与线程状态产生导演指令／触发记录主要是持久 seed + Oracle 判定loop/director.py:1
run_cascade基于事件触发地点层级／区域影响传播有限节点模型判定，可线程池并发；主线程合并事件loop/cascade.py:1
run_catchup玩家进入视野或跳时后，补充 stale 人物／地点变化有条件的模型调用；不是每次重开都刷新所有 NPCloop/time.py:1
run_lore推进任务线、期限、暗转明与终局状态以生命周期与暗骰处理为主loop/lore.py:1
_run_demote_on_leave离开区域时整理／降级相关任务状态必要时任务重排模型loop/turn.py:1
run_density按地区密度与复杂度预算补充任务骨架有条件的批量生成loop/density.py:1
scene progression位置或日期变化时推进 scene_no／scene id宿主事件，无需模型systems/scene.py:1
后台当前是“回合内后台”

没有玩家动作时，这些 hook 不会自动持续推进。ThreadPoolExecutor 的并发模型调用与持久工作队列是两回事；后续若做异步化，需要先设计任务身份、revision 过期处理、重试幂等和提交边界。
