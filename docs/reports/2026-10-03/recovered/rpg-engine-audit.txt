§1
结论
骨架是对的，功能面已经超过了设计文档，但今天还不能安心交给一个真玩家：8 条 P0 里有 4 条会让存档永久报废，2 条让「重来」形同虚设，1 条把战争迷雾在实体层捅穿，1 条会给玩家一个空白回合。项目在 7 月 7 日停在风味包的最后一步，此后两个月没有动。
做到哪了
设计文档的 S0–S5 与「活世界」A–E 全部落地：13 个可插拔系统、47 类事件、1717 个测试全绿。7 局实战，最近一局（play8）7 回合零报错、零丢段，回合中位 76 秒。风味包 9 个任务完成 7 个、2 个半成品，run.sh 的旋钮还挂在工作区没提交。
最要命的
四条「存档变砖」路径（K-01 事件先落库后投影、K-02 校验闸五个洞、K-03 时间单调硬 raise、L-14 坏 key 静默造桩世界）；纠错失效（A-01 /undo 撤的是后台事件、A-02 倒带不重置对话线程）；迷雾泄漏（M-01 隐秘地点的描述直接喂给叙事模型）；空白回合（M-02）；半截创世被当存档（L-06）。每一条都有探针在真实存档副本或引擎上复现，都是玩家会撞上的，都不是靠多补一条校验规则能堵住的。
架构判断
微内核经受住了审计：投影是纯折叠、与注册顺序无关、13 个系统零越权，fact 层的迷雾门控反复试探都没漏。缺陷集中在骨架之上的编排层，三处结构性问题：写路径没有事务也没有干跑（先落库后投影）；回合号被五个后台钩子各自分配（一个玩家回合吃掉 4 个号）；后台舰队同步阻塞叙事显示（设计文档说「非阻塞」）。再往下是 world.meta 没有 owner、FactGraph 没有索引（投影 O(F²)）、两代架构同仓共存。
测试与文档
测试质量高于预期：1688 个测试里没有一条 assert True，抽样 87% 是强断言。盲区是结构性的：默认游玩模式 multiturn 只有 16 个测试跑过；创世崩溃、倒带后的线程、校验闸的洞、apply 异常这些失败面是空白。根 README 与 SKILL.md 描述的是已冻结的第一代；自称 canonical 的 MODULE_INDEX 落后了一周的工作量。
建议
先做四件事，每件都在两三百行以内：写路径事务化加投影不可崩；回合号统一加倒带同步线程；迷雾实体层门控加重问回填散文；创世完成标记加全失败中止。做完这四件再谈风味包收尾、遗留层退役和性能。详见 §8。

§3
架构与设计缺陷
骨架是对的：事件是唯一写入口，世界由纯函数从事件折出，系统按事件类型和提交段一对一注册，叙事模型只能通过校验闸写、通过迷雾工具读。问题集中在骨架之上的「编排层」，那里把几个本该只做一次的事情做了很多次，把本该在后台的事情放在了玩家面前。

一回合的写路径。叙事在 produce 阶段就已经写好，但要等八个后台钩子全部跑完（其中五个可能再调 LLM）才打印；每个钩子后都全量重放投影；五个钩子各自分配回合号，把「回合」这个倒带用的对齐键打散了。
站得住的部分
投影是真的纯函数。内核审计用 23 个事件 × 13 个系统投影两次深比较、截断重放、软撤回重放，四项全等；47 类事件交叉喂给 13 个系统零越权；30 次随机打乱注册顺序结果 100% 一致。倒带在数据层面是可信的。
fact 层的迷雾是严密的。knows() 门控加 secrecy 白名单，用未标记的秘密反复试探一条都没漏；未知 secrecy 值 fail-closed。
provider 缝做得干净。工具循环抽成纯函数、请求构造可离线测、只有一个 HTTP 缝，1687 个测试零网络。
校验闸的形状层是硬的。字符串、裸 dict、非 dict 元素都被转成可修复错误而不是异常；工具执行层任何畸形参数都只返回 error。
结构性缺陷
写路径没有事务，投影不可崩这条不变量没人守。apply_turn 逐条 append、每条一个 commit，之后才投影；投影对单事件 apply 零防护；启动重放没有兜底。于是任何一个过闸的畸形事件都是永久变砖，而校验闸现在就有五个洞。这是所有 P0 的公共根因。（K-01、K-02、K-03、A-05）
「回合」这个键被过载了。它同时是玩家可见序号、倒带对齐键、级联触发窗口、导演冷却键，又被三种互相矛盾的方式分配（玩家号 / max+1 / 每次 append 后再 max+1）。/undo 撤错东西、级联在开局触发不了、回合号乱序，全是这一处过载。（A-01、L-03）
后台舰队不是后台。设计文档承诺 post-apply、非阻塞、廉价模型；实现是同线程串行，玩家在整条链末尾才看到文字，demote 还在用主模型。（A-03、L-10）
多轮线程与事件库是两个真相源，而且只有一方参与倒带。线程先于事件提交、倒带不通知线程、压缩只靠 usage 字段。事件溯源的可倒带性在对话层面失效。（A-02、A-05、L-12）
world.meta 没有 owner。kernel、TimeSystem、SceneSystem、DirectorSystem 四方共写，day 和 scene 的语义是「最后一条事件说了算」，后台事件一来就倒退。这是设计里唯一违反「一个键一个 owner」的地方。（K-03 路径 2、K-08）
迷雾只在 fact 层设防，实体层没有「是否已发现」的概念。Place 上明明有 tier，POV 工具从不读；三个工具殊途同归地交出隐秘地点的描述。（M-01、M-04）
FactGraph 只有「append + 线性找」一种原语。投影 O(F²)、多值关系无法退出、create 覆写，三个不同层面的问题共享这一个根因；一个 (subject, predicate) 索引加一个 close_relation 原语能一起解决。（A-04、K-07、K-04）
两代架构同仓共存。第一代的 engine/{cli,projection,seed,check,compact,archive,recall,vectorstore,rewind} 加 bin/ 加 hooks/ 加 SKILL.md 加 README，95 个绿色测试守着一个与主线零数据交集、且在部署环境里从未醒来的子系统。（A-08、D-01）

建议的处理顺序
顺序按「玩家会不会撞上 × 修起来要不要动架构」排。前四步是一批，每步都在两三百行以内、互不依赖、能各自出一个提交；做完这一批之后这套引擎才算「可以交给一个真玩家」。
写路径事务化，投影不可崩apply_turn 先在世界副本上干跑投影，通过才在一个 SQLite 事务里批量 append；project 对单事件 apply 加 try/except 记 poisoned 并跳过；meta.day 改 max 且单调、meta.scene 交给 SceneSystem；EventStore.append 拒绝 day 倒退。一次性消灭 K-01 / K-02 / K-03 / K-08 / A-05 五条，堵住所有「存档变砖」的路。
回合号只分配一次，倒带同步线程run_turn 分配一次回合号下发给全部后台钩子（density 与 scene 已经这么做）；/undo 撤「最后一个含玩家提交的回合号」；dispatch_ooc 拿到 strategy，倒带后置 _thread 为 None；commit_to_thread 移到 apply 成功之后。修 A-01 / A-02 / L-03，补一条带后台钩子的 undo 端到端测试。
迷雾实体层门控，重问回填散文统一 visible_to(pov, entity, day)，ambient / map / recall / characters 四个工具的枚举与匹配都过这一道，未发现实体不给 seed 与 sketch、拒绝空串枚举；_reask_json 成功后强制用原散文覆盖 narration。修 M-01 / M-02 / M-04。
