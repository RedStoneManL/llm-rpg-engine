§1
可行性结论
这条路走得通，而且骨架不是垃圾。「状态放在模型外面、事件溯源、战争迷雾、骰子表驱动的意外」这四条核心决定是对的，已经跑通的 7 局证明模型撑得起一个有暗线、有设定典、会藏秘密的世界。走不通的是现在的走法：把写散文、查资料、记账三件事塞进同一次模型调用，再把整支后台舰队串在玩家面前，所以一回合一两分钟、重来会失效、秘密会漏。要改的不是理念，是数据在一回合里流动的顺序。
这条路
可行
模型擅长即兴与文笔，不擅长长期一致、守秘密、算数和节奏。引擎正是补这四样的。方向没错。
现有骨架
保留约六成
事实图、事件库与纯投影、迷雾的 fact 层、Oracle 表与风味包、provider 缝与 1700 个离线测试，都值得留。
需要重排
回合流程
叙事必须先流式出来，记账和世界模拟必须离开玩家的等待路径。这一处改动决定体验，也顺带消灭大半 P0。
需要收窄
13 → 6 个系统
五套「活世界」机制、三套记忆、两代架构同仓。复杂度堆在错的地方，P0 就长在那里。
一句话判断。这是一个「地基优先、所有系统一步到位」的工程，设计文档原话是「不走可玩切片，简化版无意义」。对一个想尽快在异世界里玩起来的人，这个顺序反了：先让一回合又快又鲜活又不失忆，再往上堆机制。好消息是地基是好的，重排比重写便宜得多。
§2
从你要的体验倒推引擎的硬要求
「vivid 的异世界冒险」拆开是六件事。每一件对应引擎的一层；表里标了现在做到哪、差在哪一层，这样后面看架构图时知道该盯哪个格子。
体验要求引擎要做到现在差距在哪一层
快第一句话 3 秒内出现，整段 15 秒内读完，后台工作不让你等54–126 s 才出第一个字回合流程：无流式；叙事在 8 个后台钩子之后才显示；一次调用里做三件事
记得住几十回合前的承诺、人名、恩怨不丢，也不靠模型硬背有事实图，检索退化记忆：语义召回链断、评分与反思永不触发、「压缩」是丢弃重建、多轮线程与事件库两个真相
人是活的NPC 有自己的目的，你不在时也在做事，再见面时有变化机制在，很少触发世界模拟：catch-up / cascade 同步阻塞且触发条件苛刻；重新介绍老 NPC 会把他降级成路人
世界会动暗线自己推进，会有你没预料的事，节奏由骰子而不是模型的惯性决定两套暗线，主线会被系统了结故事线：director.threads 与 lore.lines 重复；主角线过早了结或永久休眠；每回合造一条僵尸线
有秘密NPC 知道你不知道的，模型不会漏，但线索能被你挖出来fact 层严密，实体层漏迷雾：隐秘地点的描述直接喂给叙事模型；护栏把全世界的秘密塞进 prompt 再叮嘱它别说
你说了算能重来，重来了就真的回到那一刻，模型也不再记得被撤销的事/undo 撤错东西回合与倒带：五个后台钩子各领回合号；倒带不重置对话线程
六条里有四条卡在同一个地方：回合流程的顺序。这就是为什么下面说「重排」而不是「重写」。

1回合是串行的，叙事排在最后。叙事在 produce 阶段就写好了，却要等记账、修复和 7 个后台钩子跑完才打印。
2后台钩子各自写库、各领回合号。digest / director / cascade / catch-up / lore 每个都算一次「下一个回合号」，一个玩家回合吃掉 4 个号，倒带因此撤错东西。
3记忆分散在五处半成品。narrative 摘要、kernel 子串召回、语义召回（断）、重要度与反思（永不触发）、多轮线程（不会摘要）。
4迷雾在实体层没有门。POV 工具只按 fact 过滤，隐秘地点的描述照样交给叙事模型。
5遗留层孤岛。九个文件加脚本加宪法文档，与主线零引用、协议不通、部署里从未醒来。
6编排层反向依赖入口层。loop 从 app 取常量，说明「谁拥有主角 id」没有想清楚。
713 个系统里有重复概念。director.threads 与 lore.lines 都是「未浮出的故事线」；time 与 scene 都写 meta；ontology 只是图的壳。
读法。loop 一层 7.4K 行、占全仓 42%、26 处模型调用，是全部业务逻辑的所在；它下面的 kernel 和 facts 只有 0.9K 行却是最干净的部分。复杂度堆在编排层而不是领域层，这本身就是最重要的架构信号。
§4
模块清单与判定
判定只有五种：保留、收窄、合并、重做、删除。「重做」指职责保留但流程要重写；「收窄」指砍掉一半功能保留另一半。
模块行数职责判定理由
facts/202双时态事实图保留模型最核心的资产；只需加 (subject, predicate) 索引、close_relation 与 upsert，把「非单调即 raise」改成告警。
kernel/683注册表 · 投影 · 校验 · 组装 · 时钟保留审计证明投影是纯的、与顺序无关。要补：meta 归属化、投影快照、单事件 apply 不可崩。
systems/345513 个可插拔领域系统收窄到 6留 place / character / object / faction / knowledge，把 lore + director 合成 storylines；ontology 并入 kernel 的图，time + scene 并入 kernel meta；cascade / narrative / codex 瘦身成 world tick 与记忆子系统的一部分。
loop/7396回合管线 · 创世 · 后台钩子 · 策略重做流程职责都要，顺序全错。拆成 narrate → scribe → commit → tick 四段；7 个钩子合成一个异步 world tick；甲 / 丙合成 prose-first 一种；创世改先深后广的 JIT。

§5
哪些设计是对的，哪些不对
标准只有一个：对「vivid 异世界冒险」这个目标，这个决定让体验更好还是更差。不看工程审美。
对的，留下
状态放在模型外面，模型只负责「怎么写」模型记不住几十回合、会自己改设定。事实图 + 事件库是解决失忆和漂移的唯一可靠办法。
没有它，第 30 回合的世界就不是第 1 回合的世界。
事件溯源 + 纯投影世界 = 事件的折叠，所以天然可倒带、可重算、可调试。审计用探针证明它真的是纯的。
「重来」这个功能的地基。现在坏掉的是上层用法，不是这一层。
战争迷雾作为一等公民「谁知道什么」是事实图里的事实，POV 工具据此过滤。fact 层反复试探没漏。
秘密、误会、背叛都靠它；没有迷雾的世界不 vivid。
seeded 骰子表 + 风味包便宜、可复现、防止模型每次生成同一种主角。isekai 包已经把社畜穿越、状态面板、女神外挂这些做进去了。
「意外」和「风味」最便宜的来源，直接对准你的目标。
写入必须过校验闸模型输出不可信，写世界之前要检查引用是否存在、字段是否合法。
原则对。错在让叙事者亲自产出待校验的 JSON，见右栏。
暗线有自己的节奏与生命周期暗 → 明 → 了结，由骰子而不是模型决定何时浮出，这是「世界会动」的正确抽象。
保留概念，合并两套实现。
provider 缝与离线测试一个 HTTP 缝、可脚本化的假模型、1687 个测试零网络。
重排流程时的安全网。
不对的，改掉
「地基优先、所有系统一步到位、不走可玩切片」设计文档明写的建造策略。结果是 17.6K 行、13 个系统、五套活世界机制，而一回合的手感从未被打磨。
两个月停更的根本原因：加功能比让它好玩容易。
叙事者一次调用干三件事：写散文、跑工具查资料、产出 8 段 JSON 记账这是回合慢、修复轮多、提示词与校验器打架、空白回合的共同来源。写作与记账是两种能力，硬塞给一次调用。
散文质量被 JSON 拖累，延迟被记账拖累。
后台舰队在玩家的等待路径上同步跑设计文档写「非阻塞、廉价模型」，实现是同线程串行，density 一次 72 到 107 秒。
play8 第 1 回合等 126 秒，其中 72 秒与叙事无关。
没有流式输出整个 provider 层是请求响应式，玩家面对一个转圈 spinner 一到两分钟。
沉浸感的第一杀手，与模型能力无关，纯架构选择。
两个记忆真相并存：多轮对话线程 vs 世界状态stateless 重建与 multiturn 线程两条路都保留，线程不参与倒带，「压缩」只是整段丢弃。
重来之后模型还记得被撤销的剧情。
记忆拆成五个半成品摘要、子串召回、语义召回、重要度评分、反思各自为政，两处从未在主线生效。
「记得住」只做到了一半：有事实，没有有效的回忆。
护栏把全世界的秘密塞进 prompt，再叮嘱模型别说不按场景、不按相关性，30 个远方 NPC 的秘密全在；实体层又没有可见性判定。
秘密越多越容易漏，且上下文随战役单调膨胀。
五套活世界机制互相重叠director threads、lore lines、density、cascade、catch-up、demote、endgame，各有自己的触发、模型调用和 bug。
机制越多，世界反而越安静：主线被了结、暗线永久休眠、级联触发不了。
创世一次性生成整个世界10 次调用、6 分钟，生成完就固定；密度生成再在前台补。
开局慢，而且远处的世界是「生成过」而不是「活着」。
模型分级靠环境变量叙事、记账、模拟、嵌入需要不同的模型与调用方式，现在只有主模型加一个可选的快模型开关。
没法给叙事用最会写的、给记账用最便宜的。
