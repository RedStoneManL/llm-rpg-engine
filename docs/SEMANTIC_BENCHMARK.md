# 跨回合玩法一致性实验

目的：检查角色是否在同一个连续世界里行动、记忆与交谈。这里的 performance 指
事实/叙事/角色视野表现，不以吞吐量或断点恢复作为主要成绩。

## 初始压力诊断协议（保留历史对照）

- 同一合成小镇、同一16条玩家行动、同一实际模型 `deepseek-flash`，temperature=0。
- 使用真实 `run_turn`、多轮 Author 对话和真实剧情摘要；不混入自然语言承诺登记测试。
  玉印归还约定是明确标注的合成既有历史，不伪称本轮通过模型提取。
- 保留摘要机制；关闭无关导演、暗线、密度、追赶和角色弧线演化，避免随机支线改变对照。
- 第12/15回合主动触发对话缓存重建，模拟压缩后的读取压力；这不是达到自然模型上下文
  阈值的长局实验。场景切换及摘要仍由实际机制运行。
- 原始输入、完整模型请求/响应、修复、摘要、事件和每回合前后状态全部保留；不挑成功样本。
- 每个实验臂最多64次 POST（含修复/摘要），每次最多4096输出tokens；必须注入同一个
  已授权会话预算账本。所有网络失败/预算耗尽终止继续调用，不绕路自动重试。

## 预注册检查

铜铃先在林舟手中，展示不算转移；交给沈掌柜保管后跨场景仍由沈保管，明确取回才归林舟。
玉印始终由林舟持有，直到最后归还沈掌柜；原出借人不能因玩家反问变成何桥守。
玩家依次独自去院子、石桥、集市、返回客栈；NPC不会自动跟随。第10回合明确休息到
第二天清晨。归还约定只在真正交还玉印后完成。

早期玩家称铜铃为“雨燕”，明确排除“归雁”。第15回合检查两个名字能否精确召回；
如证据丢失，承认记不清算召回失败，但优于编造。何桥守不在客栈，不能声称亲耳听到
那段话。另设一个仅沈掌柜知道的合成秘密，用于检查模型上下文和正文泄漏。

## 分开报告的指标

1. 每回合 canonical 位置、持有人、日期、原出借人、承诺状态是否符合明确行动。
2. 正文声称已经移动/交接，却没有对应事件的次数；反向遗漏也单列。
3. 编造过去说过的话、错误来源、将疑问前提当事实的次数。
4. 角色声称知道其视野之外信息，以及秘密进入提示/正文的情况。
5. 延迟精确召回成功、诚实不确定、错误记忆分别统计。
6. 玩家自主性、NPC反应和可读性人工检查。
7. token用量、调用/修复数、时延及保守费用为辅助指标，不取代玩法指标。

机器状态检查通过不能标成整段剧情一致。人工复核逐项引用原文、对应事件或源回合。
前后对照固定场景/行动/配置；单次输出仍有随机性，结果只支持本次实验，不声称普遍改进。

## 首轮发现与本轮干预

固定 Author 基线的16回合中，9次初始输出只有空格。旧路径把它变成中性占位正文，
再只修缺失的必填结构段，因而漏掉需要可选 items 的交接；错误还会沿后续回合传播。
请求仍要求 JSON 对象，而历史 assistant 消息为裸正文。这个相关性需要用对照实验
检查，不能仅凭日志就归咎于模型服务。

本轮只修同一个回合生成契约：构造请求时将历史 assistant 正文封装为 JSON，内部
原文缓存与已存历史不重写；Author 无法提供合法对象及可用正文时，在原有 repair
配额内重生成完整回合（包括实际需要的可选段），不以占位正文冒充完成。预算耗尽则
拒绝整次行动。合法、非空正文配合没有效果的回合仍可正常提交。

这不是普遍叙事一致性保证。已有完整回合的局部结构修复仍可能保留过时正文，摘要
仍会丢失精确原话，日期推理仍可能出错；这些在对照结果中继续单列，不能因空输出
减少就宣称全部记忆/玩法问题解决。

## 正常 DeepSeek 启动配置对照

另有 `scripts/benchmark_production_semantics.py`，使用同一16条行动走单次完整
`play_loop`，按仓库 `run-deepseek.sh` 的设置：16384输出、原生工具3轮、修复3次、
concise、isekai风味、多轮对话；正常后台钩子均启用，摘要/缓存按原阈值工作，不强制
压缩、不覆盖temperature，也不设置每个实验臂的总请求数闸门。工具/修复轮数是现有
生产策略，不是另外的人为实验总量限制。自然结束于16条输入完成或安全停止条件。

所有主调用、工具续答、意图识别及后台子调用共用已授权会话费用账本；每次发送前
按实际请求大小和该调用正常输出上限预留费用，不依赖账户余额耗尽来停。明确升级
未来token边界时保留历史用量和失败预留，不新建预算从零开始。

正常并发请求保留，已发出的调用正常结算；传输或预算错误后不再接纳新请求。
实验安全例外为关闭HTTP重试、禁止重定向及外部追踪；本地嵌入默认none。固定存档
是合成既有世界，未覆盖创世及完整城镇任务链。钩子启用不代表每种后台机制都触发。
机器场景检查出现偏离时须读实际事件：正当后台演化不应一律归类为剧情矛盾。

旧4096/无工具/强制压缩记录保留为压力诊断，不能与正常配置修正后数据直接作因果
对照。正常配置的前后实验使用独立Python进程和相同脚本/夹具/配置；外部传输中断
单列保留，不算玩法失败，也不从中挑选成功回合拼成完整实验。


## 2026-10-07 验证边界

生成契约改动已经过离线回归与独立代码复核。正常生产配置三次旧代码实验分别只完成
2、3、5条输入，均遭外部传输/执行中断；最后一次安全诊断明确为代理隧道HTTP403，
并伴随执行会话审批轮询取消。不能把这种中断算作游戏表现失败，也不能把这些短段
拼成完整16回合成绩。修正后生产实验尚未执行，**没有证明前后玩法改善的完整实测**。

有效的已观察证据仍保留：某些初次响应为空白或最终输出缺少JSON结构；一次正常
配置T3明确写出掌柜收铃，但只写了同名held_by事实，没有canonical物品转移。另一个
样本同一交接正常，说明生成有波动；代码修正的效果需要后续完整同配置对照确认。
旧压力实验的错误日期、虚构精确回忆和修复后正文/效果矛盾未在本次代码中通盘解决。

网络问题与密钥内容无关的现有证据是：同一密钥此前已有多次成功响应，最后错误来自
代理隧道，而不是已确认的DeepSeek认证拒绝。保留未知调用的最坏费用预留，不把失败
当作零费用；不换域名、代理或模型绕过限制。
