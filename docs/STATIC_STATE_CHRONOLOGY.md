# Static state and ordered action chronology

A real two-item handoff candidate was rejected after a local cloth-bag wording repair. Both ordered transfers matched the ledger. The final extractor anchored the same sentence's co-presence assertion after the first transfer, while the preceding transfer assertions had advanced the narrative cursor through the second. Both people remained in the same Place at every checkpoint. The host rejected the earlier anchor before checking that invariant.

The comparator now carries an earlier **location, co-presence, or passage point-state** to the existing cursor only if the identical typed predicate is supported at **every** visible checkpoint in the closed interval from the selected anchor to that cursor. It reuses the same predicate evaluator as ordinary snapshot checks. The original anchor and incoming cursor are retained in audit diagnostics, alongside the carry flag and reason.

This does not rewind the cursor, reorder transfers/movement/passage changes, infer hidden state, or accept equal endpoints when an intermediate state differs. Negative predicates retain their existing explicit-evidence rules. Historical/reported/conditional modes stay outside actual-state validation; uncertainty stays unsupported. Point custody, unknown-time custody, whole-turn custody, source-attested scene details, and the unknown-time cursor-to-final rule retain their prior scope.

The extraction schema is unchanged. Only the host comparison policy and its approval binding change; no extra model call is introduced. The actual failed transcript is preserved: one action succeeded and the next was rejected, with 12 fresh native responses total. Comparator replay accepting the same terminal candidate is not a retroactive game commit or new successful playthrough.

Remaining limits: model extraction may miss or misclassify claims. Same-sentence action claims can still arrive in an ambiguous order; this change does not sort them to manufacture success. The initial untracked-container overreach remains a separate scope issue.
