# RCV135 三地点暗线连续游玩

使用普通非 demo `build_dashboard` 默认 `GroundedAuthorStrategy`、临时 SQLite 和 9 个连续玩家行动。前台每一次作者、审稿和重写请求都逐份读取后由本会话 Terra 生成响应；实际普通控制器验证并发布。共 20 条原生请求：9 次作者、10 次审稿、1 次重写。`final/requests.json`、`responses.json` 和 `result.json` 保存逐次原始消息、响应、控制器结果、日期/地点、阶段及权限状态；没有远程 HTTP 调用。第 4 回合结束后冷重开，`reopen.json` 前后投影相同。

预设 3 条分别锚定柳溪、枫桥和青山驿的 medium 暗线，均 `cadence=day`、threshold=100、寿命 30 天、3 阶段。两次等待跨越日期，在第 2 天每线产生 stage 0、第 3 天每线产生 stage 1；同一天后续观察、往返与发言未额外推进。此推进是预设与引擎确定性事件，不是模型创作或概率分布验证。

柳溪线第 2 天的 stage 0 实际发出 `route_changed(passable=false)`，枫桥从普通玩家可移动出口消失；模型在当地观察时写出漫水封路。第 3 天 stage 1 发出 `route_changed(passable=true)`，枫桥重新成为合法出口；冷重开后玩家实际抵达枫桥，看到当地第二阶段的空菜筐，再实际返回柳溪。青山驿的两个阶段均在存档发生，但玩家没有去过，作者请求没有出现青山驿的具体信筒或信件线索。枫桥线索到实际抵达之后才出现在当地作者材料中。无实测从封闭路硬闯的对抗性输入，不据此声称覆盖所有路径绕行。

第 8 回合通过普通界面明确选择在场阿岚并说“请记住我还会回来。”，已发布的 `knowledge_set` 中逐字原话只授权给 alice，没有给远处 bob。模型最初的自然草稿写“她……目送你片刻”，而该回合没有移动；独立审稿认为“目送”容易暗示离场，返回不支持；真实重写去掉此含义，第二次审稿通过，最终正文是阿岚点头等待。是否把“目送”判为矛盾有解释余地，不能把单次审稿当成所有语义偏差均可捕获的证明。模型没有把远方发生的信件细节写成主角所见，也没有让远处人物回应该原话。

为隔离世界线与前台叙事，关闭摘要、导演、级联、追赶、密度和降暗 hook；`run_lore` 与路线结果保留。素材中的自然行动由测试者预设，不是自由玩家选择；回复和审稿来自同一 Terra 会话，是单条自生成自评。三条线设为 100% 是为了让两日变化可观测，不代表自然频率，也未测试更长寿命、复杂线终局或多个模型。场景的可见状态与作者材料由同一系统提供，不是独立的人类目击验证。

`sample/` 保留冻结前的前三回合及请求版本 mismatch：共同工作期间系统提示被更新，严格复跑因请求不一致而停止；未将其与 final 合并或用旧响应伪称新版本采样。`request_check/` 记录更新后的比较用首个请求。最终路线独立从冻结版本重新逐份生成。

重放（重建合成存档并逐请求校验既存响应，不重新采样）：

```
.venv/bin/python docs/verification/rcv135-terra-world/probe.py docs/verification/rcv135-terra-world/final
```

空目录会在每一生产请求处暂停，必须先真实生成该条原始响应并追加到 responses.json 才能继续。
