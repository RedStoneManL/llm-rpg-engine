# RCV131 Terra 连续入口验收

修前 `baseline.json` 是普通 PlayerDashboard、SQLite 与确定性模拟作者的构造反例：放下铜灯后再拾取被拒，持有人仍是客栈；较旧公开旁白仍在事件记录，但普通回忆返回空；移动后若作者未声明时间变化，要求等到次日中午却仍停在当天早晨。最后一项验证的是这种不利候选可否被宿主修正，不是模型自然输出的频率。基线探针为 `baseline_probe.py`，依赖修前 0c0cbb0 的代码运行；不要在修后工作树把同名结果当成修前证据。

修后 `after_native/` 是一次完整的 Terra 连续游玩：逐份读取生产请求，自行生成原始响应，普通 PlayerDashboard / AuthorStrategy / SQLite 逐回合验证并保存，共 4 回合 4 个真实原生响应。先放下灯（holder=客栈），再拾回（holder=主角），前往石桥集市，等至第 2 天中午。第 2 回合作者消息明确提供了可拾回物品，正文与实际持有者一致；冷重开后灯仍在主角手中、位置和时钟均保持。撤销最后等待后仍在集市且灯仍在主角手中，时间回到第 1 天早晨。

测试存档预先写入一条合成公开旁白“朱橘纸鹤停在第三块石头”和 9 条后续旁白，使该旧句不在最近 8 条界面记录中。普通 `dashboard.recall` 找到带日期、回合、类型和 ref 的原句；`open_source` 打开该句，并显示之前一条及之后两条公开旁白。撤回后旧版本 ref 被拒并要求重新检索，重新检索仍找到旧句。这是旁白原文，不是玩家输入档案或明确收件人原话；更长历史、不同语言检索及权限隔离由其他回归覆盖，本样本不能替代那些测试。模型请求中摘要积压仍可包含该句，因此这里验证的是普通回忆入口，不是证明作者已看不见它。

此样本的模型主动为“等至明天中午”声明正确 clock，因此不能据此证明模型漏声明时宿主必能补全，须看单独的对抗性离线回归。为隔离入口本样本关闭摘要、级联、追赶、导演、密度和降暗 hooks，保留 run_lore；无远程 HTTP、无真实玩家存档，单条同模型生成与自评不代表模型总体稳定性。原始生产 requests / responses、每回合物品/时钟状态、冷重开、回忆、打开来源和撤回结果在 `after_native/` 中。

重放：

```
.venv/bin/python docs/verification/rcv131-terra/native_probe.py docs/verification/rcv131-terra/after_native
```

重放会重新构造临时合成存档并比较实际请求，但不会再次采样模型。空目录会在每次真实请求处暂停，需逐份生成原始响应并追加 responses.json。
