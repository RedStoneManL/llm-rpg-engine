## 玩家问题与实现

用户要求优先游戏体验。此前 Hybrid 先写正文，再补结构；结构修正后仍可能保存最初的成功描述。
默认 Author 的局部修复也把原正文视为不变内容。现在：

- Hybrid 复用 Author 的上下文、工具研究和结构修复，先提出效果，再由 `produce_turn` 校验；
  效果通过之后才调用最终散文生成。正常两次作者调用，不增加为三次。
- Author 结构没有变化时保留一次调用；结构修正或引用补齐改变候选后，才做一次最终散文生成。
- 最终作者收到本次已经过滤的语境、宿主资源结果和最终 sections；不复用被否决的候选、修复对话或草稿。
  风格、篇幅、会话软方向仍生效。自然对白与反应可以创作，但不授权重新决定持久效果。
- 最终阶段只接回字符串，传入 commit 为独立副本。空正文、JSON 混入、明显复述等可重写一次；
  不再进行结构规划或执行付款。重写仍失败或取消时不发布；通过后只保存最终正文。
- duplicate、冷重开和多轮作者缓存都恢复／记住最终正文；既有原子事务、后台和撤回语义继续工作。

`HybridStrategy.produce()` 现在只返回内部提议，直接调用者必须通过 `produce_turn` 完成最终正文；
`run_compare` 和普通 GUI 已走这条链路。外部自行调用 produce→apply 的集成需适配此语义。
旧测试中“结构修了但正文永远不变”的断言按新行为更新，保留局部修复、通过段不变和零写入等原有检查。

## 实际验证

环境 Python 3.12.14 / pytest 8.4.2，使用现有独立 `.venv`。

```bash
.venv/bin/python -m pytest -o "addopts=-m 'not slow'" -q
```

- 修改前重新执行：**2171 passed, 1 deselected in 37.95s**。
- 新反例首跑：10 个案例中 **7 failed / 3 passed**；失败复现调用顺序、陈旧正文、无效结构仍耗正文调用及正文失败发布等问题。
- 扩充后的专项：**229 passed in 4.23s**。涵盖 14 个新案例及策略、compare、资源、普通 GUI、clock、trace、回合和响应恢复回归。
- 首轮全量发现 5 个旧替身没有提供新增的最终散文响应，得到 **5 failed, 2176 passed, 1 deselected**；
  已明确补齐替身协议，没有放松正文验证或扩大跳过。
- 最终全量：**2185 passed, 1 deselected in 39.62s**；唯一 deselect 仍为既有 slow real embedding。

新增检查包括：正常 GUI 的结构→最终正文顺序；Author／Hybrid 修正事实后换掉旧描述；默认一次调用；
不可达移动只修结构再写正文；结果无效时不生成正文；正文异常／取消零写；正文重写仅扣款一次；
余额不足传至最终作者；多轮缓存不含草稿；副本修改不影响已接受效果；冷重开 duplicate 不重新生成；撤回恢复余额。
