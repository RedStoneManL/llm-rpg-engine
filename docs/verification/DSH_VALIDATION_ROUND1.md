# DSH 候选机制验证：第一轮

日期：2026-11-11（北京时间）

结论：先验证、消融，再逐项接入。本轮已经运行真实第三方组件，发现一个不满足严格角色认知隔离的召回路径，同时确认摘要谱系回滚的必要性。**生产运行时尚未接入任何第三方机制。**

真实模型调用为 **0**。独立实验使用真实 SQLite、真实文件系统、真实检索和提示词组装代码。没有测试完整 DSH 启动、插件 UI、真实 NPC 决策质量、跨平台安装、生产 token 或远端模型延迟。

## 发现 1：角色知道的事不变，幕后真相却能改变召回

**准入状态：阻止直接接入该召回路径。**

构造两个世界，NPC 的两条感知完全相同：

1. “一个穿灰衣的男子从库房走出来。”
2. “掌柜在大厅喝茶。”

两份输入的感知文本、摘要、模式、事件时间、重要性、涉及人物和标签都做了相等断言。仅第一条事件的幕后原文不同：一个世界是普通进出库房，另一个是“银月密钥藏在库房暗格”。

向 NPC 提出完全相同的问题：“掌柜的银月密钥在哪里？”在 recall=1、无遗忘、无关联扩展、无多样性重排的固定条件下：

| 实现 | 普通幕后原文 | 含密钥的幕后原文 | 相同可见输入得到相同回忆？ |
| --- | --- | --- | --- |
| 原始召回组件 | 掌柜在大厅喝茶 | 灰衣男子从库房出来 | **否** |
| 仅屏蔽排序输入中的幕后 event.text | 掌柜在大厅喝茶 | 掌柜在大厅喝茶 | 是 |

根因定位到 recall.ts 的 gather：词面匹配同时使用 perception.content 与 event.text。召回输出虽然仍是角色自己的感知，但**选择哪段感知的过程已经受未公开真相影响**，可能给角色提供本来无法形成的关联。

这证明的是组件的数据依赖问题，不是“NPC 直接输出了完整密钥秘密”，也没有测其实际发生频率。

本次仅移除了 event.text 的影响。没有因此宣布修复完成：标签、参与者、重要性、地点、FTS／向量索引与 reranker 仍需审计。可接受的方向是在检索之前构造角色可见候选集，所有检索与重排只消费这个候选视图。

## 发现 2：独立人设有效，但必须同时隔离记忆与公共场景输入

同一资料库中，A 有搬货经历，B 有带私密标记的密钥经历。使用实际 sharedContext.brief 组装 A 的输入：

| 变体 | B 的私密记忆进入 A 的 prompt | B 的私人背景进入 A 的 persona |
| --- | --- | --- |
| 原始按角色读取 | 否 | 否 |
| 只取消感知库的角色过滤 | 是 | 否 |

因此，“分别写人设”不足以保证隔离；数据过滤对本场景有明确贡献。两个输入分别约 2277、2319 UTF-8 字节，仅是该场景的输入大小，不能换算成实际 token／费用收益。

另一个契约测试向公共 situation 塞入秘密标记，实际提示词构造器会原样带入。这不是证明完整插件必然泄露，而是说明构造器信任上游输入。我们接入时必须在形成 situation／earlier reactions 等字段前完成视角过滤。

## 发现 3：证据存在与“证据支持结论”不是一回事

运行真实 proposalProblems → editOf → SQLite 写入链路，消融仅关闭前置 proposalProblems：

| 提案 | 完整校验 | 关闭前置校验，保留真实写入校验 |
| --- | --- | --- |
| 两次有关掌柜失信的经历 → 怀疑其不守承诺 | 接受 | 接受 |
| 引用不存在的感知 ID | 拒绝 | 写入层仍拒绝 |
| 引用另一个 NPC 的私人感知 | 拒绝 | 写入层仍拒绝 |
| 两次掌柜失信的经历 → “井底藏着一条蓝龙” | **接受** | **接受** |

有两个不同结论：

- 对不存在／越权引用，写入层有额外保护；这组消融没有证明前置检查提高最终阻断率。它可能改善修复反馈，但本轮没有测这个收益。
- 合法 ID 与多回合证据数量不能保证语义相关。无关结论仍能进入信念库；完整模型流程是否会产生这种提案，需要真实模型测试。

在所有变体中，世界事件原文和另一 NPC 的信念库都未被修改。这支持“信念与事实分层”的存储机制，但不证明信念生成质量。角色可以误解；系统仍应区别有依据的错误理解与无关引用拼接。

## 发现 4：摘要谱系回滚确有收益，值得优先借鉴其规则

用实际文件、MemoryStore、WAL 和 snapshotStory：

- 第 1 回合获得铜钥匙。
- 第 2 回合约定未来在钟楼密会。
- 将两个来源归档，形成同时包含过去和未来的摘要。
- 从第 1 回合之后创建子分支，父分支内容做完整文件摘要比较。

| 变体 | 子分支残留未来信息 | 检索还能命中未来信息 | 过去信息保留 | 父分支未改动 |
| --- | --- | --- | --- | --- |
| 快照 + 回滚 + 摘要展开 | 否 | 否 | 是 | 是 |
| 只关闭回滚 | 是 | 是 | 是 | 是 |
| 保留回滚，仅关闭受影响摘要展开 | **是** | **是** | 是 | 是 |

关闭摘要展开时，对实际被调用的 expandAffectedMemories 做 spy，并断言干预发生；其余回滚和文件代码照常执行。

额外注入“草稿准备到一半抛错”：子分支没有发布，父分支不变，临时草稿被清理。

本轮可以支持下一步借鉴以下不变量：**回滚必须撤销或重建依赖已撤销来源的摘要、索引和认知，子分支准备成功后才能发布。** 不因此把第三方文件 WAL 整套复制进我们的 SQLite 内核。后台任务、模板变量、宿主 inbox 与跨进程崩溃仍不在独立实验覆盖内。

## 发现 5：遗忘适合角色体验，不适合逐字档案查询

这组只测基础词面召回组件，未接入向量或 reranker。三个变体共享 21 条经历和相同查询预算：recall=4、associate=0。default 仅表示沿用默认遗忘参数，其他组只关闭 flaky 或使用最近四条窗口。

对“通行证放在哪里”：

| 距离经历的游戏天数 | 开启遗忘：能否召回／保持原话 | 关闭遗忘 | 最近四条窗口 |
| --- | --- | --- | --- |
| 0、7、30 | 能召回，保留原话 | 能召回，保留原话 | 找不到旧经历 |
| 90、180 | 能召回，**原话已模糊化** | 能召回，保留原话 | 找不到旧经历 |

改问“进城凭证收在哪儿”，本组基础词面路径在全部五个时间点均未召回目标。这个小样本说明纯词面路径的边界，不能据此说整个插件的语义检索不可用，也不能把“关闭遗忘”当作语义检索修复。

我们的接入方式应保留两条不同路径：角色可以有遗忘与不确定性的回想；玩家查原话必须使用完整来源记录，不能用角色回忆代替。

## 对自己的同等要求

新增两个反事实测试，分别覆盖：

- 角色未获知的秘密目标发生变化。
- 角色保持同一认知，幕后真实目标发生变化。

实际执行本引擎的 assemble_context、POV recall 和 recall_query，结果保持相同；关闭 POV 过滤的负对照能够检测出幕后变化。第二组还明确断言角色自己的认知确实进入上下文。

这支持当前玩家／作者读取边界；不能外推成尚未接入的自主 NPC 流程已全部正确。

## 本轮准入决定

| 候选机制 | 当前决定 | 下一步要求 |
| --- | --- | --- |
| 按角色限定数据／工具／记忆 | 可进入独立适配试验 | 扩大到全部检索字段、公共场景与工具元数据；同场耳语、转述、离场场景 |
| Agentic Roleplay 当前基础召回 | **暂不接入** | 消除隐蔽真相对候选与排序的影响；补 FTS／向量／reranker 反事实用例 |
| 感知／信念分层 | 保留候选 | 加语义证据评估和真实模型误解／反证场景；不把结构校验等同于正确推理 |
| 受影响摘要回滚、草稿分支发布 | 优先进入我们内核的最小适配试验 | 沿用自身 SQLite 事务，在统一来源依赖上测试撤销、后台迟到结果和重开 |
| 拟人遗忘 | 只考虑角色回想模式 | 档案查询仍保持完整；先确认玩法收益再决定默认启用 |
| 独立 NPC 与导演／编辑多 Agent 全流程 | 尚未准入 | 同模型／同预算真实场景，比较行为、信息隔离、调用数、token 与延迟 |
| 完整 DSH 插件交付 | 尚未准入 | 实际安装、生命周期、会话绑定、取消与恢复、UI 和平台兼容 |

本轮合入范围限定为实验、复现工具、结果和准入规范，**运行时接入数量为 0**。后续每一批接入只带一个机制、明确收益、失败场景与回退方式。候选功能不因上游自述或测试数量多而自动通过。
