# RCV-125：交付约定、迟交与下一回合的公开结局

日期：2026-11-04（Asia/Shanghai）。起点 `3fcec30`（RCV-124），Python 3.12.14、pytest 8.4.2。
本轮按用户要求边修边测，限定 Terra 测试角色；没有启动并行实现团队。

## 玩家能看到什么

接取明确的单件交付任务后，任务账本记录物品、接收者及可选截止时段。
实际交出物品才结算；只声明完成而没有交付，进入既有有界修复流程，耗尽则整回合不发布。
作者忘记写任务完成时，宿主从实际转移补齐结算。逾期保留任务与补救机会，不自动判失败。
明确放弃显示“已放弃”，不会伪装成交付成功；GUI 分类改为“已结任务”。

正常作者结构因结算改变后，沿用 RCV-122 重写最终正文；Hybrid 仍先确定结果再写正文。
下一回合注入最近六条已经公开的玩家结案结果，按实际结案顺序排列，不再刚结案就丢失语境。
后台未向玩家公开的世界结局不会进入这张卡。无新事件类型、迁移、默认私有解释或奖励系统。

## 实现与协议

- `kernel/quest_outcomes.py`：纯函数校验、转移证据、按回合结束时钟结算、共享账本文案。
- `systems/lore.py`：open 保存 objective，resolve 保存宿主 resolution，事件重放恢复公开结局卡。
- `loop/turn.py`：候选校验 → 宿主结算 → 重验 → 最终正文 → 事件物化／发布复核；重写不再次执行效果。
- `context/capabilities.py`：复用当前背包及本地公开接收者集合；`app/player_objectives.py` 复用同一状态文案。

```json
{"op":"open","id":"deliver_medicine","summary":"中午前交药",
 "objective":{"kind":"deliver","item":"medicine","recipient":"apothecary",
              "due":{"day":1,"band":1}}}
```

due 可省略。band 为 0晨／1中午／2下午／3夜；截止时段包含边界，比较使用最终回合时钟。
初始切片要求先接取、之后回合再交付；不支持同回合新建约定并转移该物品。
一个目标是一件唯一 Object；不是物品数量、货币支付、赴约、护送或通用任务 DSL。
同一唯一物品和同一接收者的多个约定可由一次交付共同履行，各自按期限计算；不生成奖励。
同回合交付再拿回不算完成；同回合“交付且放弃”拒绝。既有交付条件不能在 advance/resolve 时改写。

已经由其他路径交给目标的物品，只有 held_by 关系的 ingest_turn 晚于接取 turn 才能作为补登记证据。
这类旧关系缺少精确时段，明确记录 timing=unknown，不能用补登记时刻冒充交付时刻。
无 objective 的旧任务继续使用原有自由叙事结算，不被强制解释成物品交付。
任务卡是当前状态和结局提示，不是逐字原文证据；精确记忆仍不能从它反向编造。

## 实际验证

初始 15 个新例在旧实现下得到 **14 failed / 1 passed**。接线后全部通过。
第一次全量：**2 failed, 2204 passed, 1 deselected in 41.29s**；失败为两处旧断言要求所有结案内容
从作者上下文消失。改为检查“移出明账、进入近期结局”，保留测试且没有扩展跳过范围。

最终新增 29 个交付相关案例；专项 **117 passed in 4.19s**，涵盖期限边界、跨日、迟交可补救、
口头声明无转移、放弃、错收件者、过去持有不算履行、无法核实旧交付时间、同回合取回、重复约定、
最终事件丢失、宿主修正时机、六条结局排序、暗线结局隔离、重复提交、撤回和冷重开。

完整门禁命令：

```bash
.venv/bin/python -m pytest -o "addopts=-m 'not slow'" -q
```

最终 **2220 passed, 1 deselected in 40.06s**；唯一未运行项仍为原有 slow real embedding，没有下载权重。
`pip check` 与 `git diff --check` 通过。

## Terra 原生游玩

运行 `scripts/verify_delivery_native.py next docs/verification/fixtures/rcv125-terra`，逐请求暂停，
由本会话可用的 **gpt-6.1-terra** 读取原始生产提示并现场生成响应，再精确回放。
保留 requests／responses、SHA-256、result 与 review；不填入 fake 响应冒充原生模型。

**5 个行动、10 个真实生成响应通过**：接取 → 等到下午 → 只在心里构思谎言但没说出口 → 实际迟交 →
观察后续。第4回合候选仅有物品转移，宿主补 resolve 和 late；正文药师收药并问为何耽搁。
第5回合实际提示含近期迟交结局，未重复交药或编造奖励。机械冷重开、重复提交与两次撤回也通过。
Terra 另外实际核验跨日第2天下午的迟交与无 objective 的旧任务结案，未发现新回归。

这是人工合成、前台隔离的单条样本；不相关后台 LLM hooks 被禁用，真实 run_lore 保留。
不是远端 HTTP transport、付费 provider、多次采样、说出口的谎言、长期可玩性或浏览器布局验收。
生成者同时评审存在偏差。我的复核与 Terra 一致：人物反应连贯，但偏平淡，最后一轮推进有限；
没有把这种表现写成“剧情质量已全面验证”。重启／撤回后的机械一致性与之后的长期人物表现是不同证据。

无推送、部署、凭据修改或 Library／Drive／邮件上传。下一优先项是按实测改善局面推进与回合等待，
先测现有开销，再处理多余工作；更完整的任务种类与角色自主行为仍在设计中。
