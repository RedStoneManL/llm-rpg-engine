# 6.1 Terra DM 真实运行结果

2026-11-11，按用户指定使用 `gpt-6.1-terra`。起点为 `9acb6f3`，其生产代码基线是 `91646fb`。本轮运行正式玩家入口与 SQLite，第三方 DSH 机制没有直接并入。

## 结果

初跑在第 5 个行动失败。保留失败记录、修复边界不一致后，从失败前存档续跑，最终共提交 11 个剧情行动，另做 1 次撤销和 2 次冷重开。初跑 12 次、续跑 23 次，共 35 次真实模型响应。模型在撤销后主动调用 1 次 `history_locate`。

调用分布：作者／工具回合 13，正文校验 11，最终正文重写 2，暗线生成 2，摘要 5，暗线重排与人物追赶各 1。后台 hook 没有禁用，但某个 hook 没有模型请求不代表执行失败：它可能是确定性操作或尚未达到触发条件。

这里的“真实”指指定模型根据正式请求逐次生成，经过真实校验和存档。模型通过原生 agent 与本地 mailbox 交换请求，没有远程付费 HTTP 调用。请求哈希逐份对应，未伪报 token、API 延迟或 DSH 安装结果。正文校验也使用同一模型，不把它的自评当作独立证据。

## 发现并修复的实际阻断

导演先触发“认错人”。Terra 在第 5 个行动生成新信使，同时写入她的来源陈述和主角获知记录。角色创建／来源校验允许同回合登场，普通 facts 权限却只认可行动开始时已存在的人物，造成整回合 `TurnRejected`，时钟也未前进。

修复让候选与最终事件校验共用 `turn_speaker_material`：保留原有 POV 过滤，纳入实际合法抵达的公开人物，以及同回合创建并明确放置在本地的全新公开人物。新人物身份必须不存在，声明不能带 past/hidden，位置不能缺失、远离玩家或互相冲突；只有 public 的 reported: 转述获得此权限，不能借此写 canonical 真相。

最终 payload 会从实际创建、移动、地点、事实与认知事件重新构造同一规则，不依赖候选已经通过。源事件被篡改删除人物到场时仍拒绝。现有 NPC 的演化权限没有随之扩大。

未改动原失败响应的重放对照：修前 `player_fact_authority_boundary`，修后正式 dashboard 完成提交，信使位置、转述与主角获知记录均落库。重放只证明机制改动；后续 23 次响应是新的 Terra 生成，二者分别记录。

验证：先复现 2 个红例；修后 58 项相关测试通过；全量 2276 passed、1 deselected；另补两个边界后 11 项专项通过。修改保留在研究分支，尚未合入原生产分支。

## 还不满意的体验

1. 第 5、7 个行动连续出现“认错人”。两个独立 director_fired 记录都抽到了相同 twist，因此根因是缺少近期主题去重，而不是模型没有读懂两段文字。下一项应验证导演主题冷却／去重的消融收益。
2. 对话连贯但偏短，几次行动的可选后续不够鲜明。菜摊线给出了可回应的帮忙请求；船契线仍只停留在钩子，本轮未测到任务结局。
3. “我看过旧告示”的亲历措辞仍值得单独核验。原数据只写了知识来源“旧告示”，正文审查返回 supported=true 不足以证明所有来源表述都精确。
4. 未测试大上下文 compaction、跨进程后台任务迟到、几十回合的人格与剧情漂移，也未做多模型质量比较。

## 对 DSH 接入方案的影响

这次直接支持的工程选择是：先把现有引擎的一次完整行动封装为插件工具，继续由内核管理存档、来源、视角过滤、校验与撤销。DSH 负责会话和交互；不要让宿主模型绕过事务直接拼写 facts／knowledge。

第三方摘要谱系回滚仍值得优先做独立适配；已发现幕后真相影响召回的路径继续阻止直接接入。新增机制先进入相同场景的对照分支；通过组件与本引擎回归后，再做真实模型和实际 DSH 宿主验证。

本轮没有启动 DSH，没有测插件安装／发布，也没有据此宣布迁移完成。可阅读的 HTML 回放由 `experiments/terra-live/review.py` 从原始证据生成；详细数据位于同目录 `terra-live-20261111/`。
